# A gate on one layer can push the problem down

A small router can point to an enormous index. A tidy index can open a journal
containing months of unrelated lessons. A hard rule can fit its cap only because
the command needed to obey it was moved into a background file nobody opens.
Measuring one layer alone makes that layer look healthy while its readers pay elsewhere.

The ladder puts a job and a budget on each layer. The router contains triggers,
hard rules and active-work pointers. Activity and domain indexes route to atomic
lessons and topics. A state file holds one current block, overwritten at checkpoints.
Hard rules retain every operational value and send only history and explanation to
backgrounds. Project facts live in the project's typed brain, with memory pointers.
Git retains earlier state. Roadmap and log history rotate out of the live surfaces.

Figures below: measured in real memories; not performance guarantees.
In real memories, migration reduced hard-rule trigger bytes from 85.9 KB to 14.9 KB;
search probes improved from 16/25 to 22/25. Rotation reduced the live
roadmap from 434.7 KB to 32.8 KB and removed 103 gate exceptions. These figures do not guarantee the same results elsewhere. Start with your own
measurement and probes, and compare after normal sessions before declaring success.

Byte proofs answer whether content survived. They cannot prove that an instruction
still fires at the right time, that pending work remains visible, or that a rule kept
the exact quota, account, command and path required to obey it. Conversion therefore
combines token presence, exact blocks for whole-file moves, a gate, recall probes,
and a different model comparing every original imperative with the rewrite.

One engine supports direct installation and integration into other setup tools.
There is one version and one owned-file manifest.
Project config, probes and memory remain project-owned. A beta makes installation
and measurement possible now; broader adoption follows evidence from normal use.
